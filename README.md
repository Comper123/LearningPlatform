# imlearning

Система контроля процесса обучения в центре образования по программированию:
ученики, группы, курсы, занятия, посещаемость, домашние задания, прогресс по темам.

## Стек

- Next.js 16 (App Router) + TypeScript
- Tailwind CSS v4
- PostgreSQL (Supabase) + Drizzle ORM
- NextAuth v5 (Google OAuth, сессии в БД)

## Роли и регистрация

### Главный принцип

Роль **никогда не выбирается свободно**. Если бы форма регистрации просто
спрашивала «вы ученик или преподаватель?», любой посетитель сделал бы себя
преподавателем и получил собственный кабинет с чужими данными рядом. Поэтому у
каждой роли свой ключ, и разделение держится не на форме, а на проверке ключа
на сервере.

| Роль          | Что нужно предъявить                               | Кто выдаёт             |
| ------------- | -------------------------------------------------- | ---------------------- |
| Преподаватель | адрес в `TEACHER_EMAILS` **или** `TEACHER_SIGNUP_CODE` | вы (через `.env`)      |
| Ученик        | код-приглашение преподавателя (вида `K7QF-2M9X`)   | преподаватель          |

Код преподавателя генерируется автоматически при первом входе и виден на
странице «Ученики».

### Два способа входа

Оба работают для обеих ролей:

- **Email + пароль** — `/register/student` и `/register/teacher`. Пароль
  хранится как bcrypt-хеш в `user.password_hash`.
- **Google** — кнопка на тех же страницах.

Один и тот же email через пароль и через Google — это один аккаунт
(`allowDangerousEmailAccountLinking`). Так человек, зарегистрировавшийся
паролем, может потом войти через Google и не завести себе двойника. Это
безопасно, потому что Google подтверждает владение адресом.

### Что происходит после входа через Google

У Google-регистрации нет поля для кода, поэтому роль назначается так:

1. email есть в `TEACHER_EMAILS` → сразу преподаватель;
2. email совпал с карточкой ученика, которую преподаватель завёл заранее →
   сразу ученик, карточка привязана к аккаунту;
3. иначе роль `pending` — человек попадает на `/onboarding`, где выбирает
   «я ученик» (нужен код преподавателя) или «я преподаватель» (нужен ключ).

Пока роль `pending`, пользователь не видит вообще никаких данных — только
экран ввода кода. Проверки живут в `requireTeacher()` / `requireStudent()`
(`src/lib/session.ts`), а не в разметке страниц.

### Заявки на зачисление

Самозапись по коду не даёт доступа сразу — она создаёт **заявку** (карточка
ученика в статусе `pending`). Пока заявка не рассмотрена, ученик видит только
экран «Заявка отправлена» и никаких учебных данных.

Преподаватель видит заявки блоком на странице «Ученики» и баннером на главной,
принимает (`active`) или отклоняет (`rejected`) одной кнопкой. Отклонённый
ученик видит объяснение и может связаться с преподавателем — заявку можно
принять позже, данные не теряются.

Карточки, которые преподаватель завёл сам, подтверждения не требуют: они сразу
`active`, ведь их создал сам преподаватель.

### Три пути ученика в систему

1. Преподаватель заводит карточку с email → ученик регистрируется сам любым
   способом → карточка подхватывается по email.
2. Ученик регистрируется паролем на `/register/student` с кодом → карточка
   создаётся сразу.
3. Ученик входит через Google → вводит код на `/onboarding`.

## Запуск

1. Скопируйте `.env.example` в `.env.local` и заполните:

   - `DATABASE_URL` — Supabase → Project Settings → Database → Connection string
   - `AUTH_SECRET` — `npx auth secret`
   - `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` — Google Cloud Console → Credentials →
     OAuth client ID (redirect URI: `http://localhost:3000/api/auth/callback/google`)

     ⚠️ **Порт должен совпадать.** Если 3000 занят другим проектом, Next.js
     молча поднимется на 3001, и Google ответит «Ошибка 400: invalid_request»,
     потому что такой redirect URI не зарегистрирован. Либо освободите 3000,
     либо добавьте в Google адрес с фактическим портом и пропишите тот же
     порт в `AUTH_URL`.
   - `TEACHER_EMAILS` — ваш адрес, чтобы получить роль преподавателя
   - `TEACHER_SIGNUP_CODE` — ключ для регистрации других преподавателей;
     оставьте пустым, если преподаватель в системе только вы

2. Примените схему к базе:

   ```bash
   npm run db:migrate
   ```

3. Запустите dev-сервер:

   ```bash
   npm run dev
   ```

## Что уже работает

**Преподаватель** (`/dashboard`)

- сводка: ученики, группы, ближайшие занятия, работы на проверке
- ученики: список, добавление, карточка с посещаемостью, домашками и прогрессом
- курсы: программа темами, порядок тем меняется стрелками
- группы: состав, запись и отчисление, список занятий
- сводка посещаемости по группе: матрица «ученики × занятия» с процентом
  посещения у каждого
- занятия: календарь по месяцам и список, журнал посещаемости в один экран,
  конспект
- расписание группы: слоты вида «Вторник, 18:00, 90 мин» и автоматическая
  расстановка занятий на N недель вперёд с проставлением тем курса по порядку
- материалы занятия: редактор Markdown с панелью вставки и предпросмотром
- домашние задания: выдача на всю группу, проверка с баллом и комментарием;
  решение видно прямо на странице проверки — ссылкой, кодом или файлом
- прогресс: уровень освоения темы 0–5 в один клик

**Ученик** (`/me`)

- свои группы и история посещаемости
- домашние задания: сдача ссылкой, вставленным кодом или файлом, оценка и
  комментарий преподавателя

## Supabase Storage: вложения к домашним заданиям

Функция необязательная. Без неё ученик сдаёт работу ссылкой или вставленным
кодом, а вкладка «Файл» просто не показывается.

**1. Создайте бакет.** Supabase → Storage → New bucket:

- имя: `submissions`
- **Public bucket: выключено.** Работы учеников не должны быть доступны по
  прямой ссылке любому, кто её угадает.

**2. Возьмите ключи.** Supabase → Project Settings → API:

- `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
- `service_role` (не `anon`!) → `SUPABASE_SERVICE_ROLE_KEY`

**3. Пропишите в `.env`** — как в `.env.example` — и перезапустите dev-сервер.

**RLS-политики не нужны.** Мы ходим в хранилище только с сервера сервисным
ключом, который RLS обходит. Ключ никогда не попадает в браузер: модуль
`src/lib/storage.ts` помечен `server-only`, и сборка упадёт при попытке
импортировать его в клиентский компонент.

Как это работает:

- файл кладётся по пути `<задание>/<ученик>/<время>-<имя>`, до 5 МБ;
- преподаватель получает **подписанную ссылку на час** — постоянных
  публичных ссылок на работы не существует;
- имя файла очищается от небезопасных символов при загрузке.

## Тестовые данные

```bash
npx tsx scripts/seed.ts
```

Создаёт два курса с программой, три группы с расписанием, 12 учеников, одну
заявку на зачисление, занятия за 6 недель назад и 4 вперёд с посещаемостью,
домашние задания в разных стадиях проверки и оценки прогресса по темам.

- ничего не удаляет; если курсы уже есть — просит флаг `--force`
- `--clean` убирает только созданное скриптом: курсы и группы с точными
  названиями и учеников с почтой `@example.com`
- если преподавателей несколько, укажите email: `npx tsx scripts/seed.ts you@mail.ru`

## Если drizzle-kit не работает

`db:push` падает на чтении схемы, `db:migrate` иногда виснет на пулере
Supabase. Обходной путь — выполнить SQL напрямую:

```bash
npx tsx scripts/apply-sql.ts drizzle/0004_known_captain_universe.sql
```

Скрипт разбивает файл по `--> statement-breakpoint` и выполняет выражения по
очереди, печатая результат `SELECT`. Учёт в `drizzle.__drizzle_migrations` при
этом не ведётся — миграция считается непримененной, но все наши файлы написаны
идемпотентно, так что повторный прогон безвреден.

## Миграции: подводный камень с enum

Мигратор drizzle выполняет **все** непримененные миграции в одной транзакции, а
PostgreSQL запрещает использовать значение enum, добавленное через
`ALTER TYPE ... ADD VALUE`, до конца этой же транзакции. Если drizzle-kit
сгенерировал `ADD VALUE`, а следом — что-то, что это значение использует
(`SET DEFAULT`, `UPDATE`, `WHERE`), транзакция упадёт с «unsafe use of new
value» и не применится **ни одна** миграция.

Поэтому после `npm run db:generate` проверяйте новый файл: если там есть
`ALTER TYPE ... ADD VALUE`, замените его на пересоздание типа — как сделано в
`0002` и `0003`. Значения типа, созданного в текущей транзакции, использовать
можно, ограничение касается только дополнения уже существующего типа.

## Модель данных

`src/db/schema/` — `auth.ts` (NextAuth + роли + коды приглашений),
`app.ts` (учебные сущности).

- **students** — карточки учеников; `user_id` связывает карточку с аккаунтом
- **courses → topics** — программа курса упорядоченным списком тем
- **groups → enrollments** — группы и их состав (отчисление сохраняет историю)
- **schedule_slots** — регулярное расписание группы, по нему занятия
  расставляются автоматически
- **lessons → attendance** — занятия и отметки присутствия
- **assignments → submissions** — задания, сдачи, баллы, фидбек
- **topic_progress** — уровень освоения темы учеником (0–5)

Всё привязано к `teacherId`, поэтому несколько преподавателей могут работать в
одной базе, не видя данные друг друга.
